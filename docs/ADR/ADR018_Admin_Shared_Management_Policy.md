# ADR-018. 관리자 공동 관리 정책

## 배경

새소식은 개인 게시물이 아니라 게임 운영자가 사용자에게 전달하는 공식 콘텐츠다.
관리자 계정이 여러 개인 경우 최초 작성자만 수정하거나 삭제할 수 있도록 제한하면 운영 인수인계와 긴급 대응이 어려워질 수 있다.

## 결정

새소식 수정과 삭제 권한은 작성자 여부가 아니라 요청 시점의 최신 회원 상태와 역할을 기준으로 판단한다.

- Service는 쓰기 요청마다 memberId로 Member를 DB에서 다시 조회한다.
- 최신 `MemberStatus`가 `ACTIVE`이고 최신 `MemberRole`이 `ADMIN`인 경우에만 작성, 수정, 삭제를 허용한다.
- ACTIVE ADMIN이면 다른 관리자가 작성한 새소식도 수정하거나 삭제할 수 있다.
- 작성자 일치 여부는 검사하지 않는다.
- 다른 관리자가 수정해도 writer는 최초 작성 관리자로 유지한다.

## 이유

- 새소식은 관리자 개인의 콘텐츠가 아니라 운영 조직이 공동 관리하는 공식 콘텐츠다.
- 여러 관리자가 공지 수정과 긴급 삭제를 이어서 처리할 수 있다.
- 세션에 저장된 과거 권한만 신뢰하지 않고 최신 DB 상태와 역할을 확인할 수 있다.
- 최초 writer를 유지하여 최초 작성자를 감사 및 운영 추적에 활용할 수 있다.

## 결과

- SecurityConfig의 `/api/admin/**` 규칙이 세션의 ADMIN 역할을 1차 검사한다.
- NewsService가 최신 ACTIVE ADMIN 여부를 2차 검사한다.
- 로그인 후 정지, 탈퇴 또는 USER로 역할이 변경된 기존 ADMIN 세션의 쓰기 요청은 Service에서 거부된다.
- 수정 및 삭제 권한은 최초 writer와 무관하다.
- 공개 News 응답에는 writer 정보를 노출하지 않는다.
